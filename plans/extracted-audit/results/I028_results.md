## Findings and corrections

- **FM-A6 corrections** (the code disagrees or the names moved):
  - The two operands of the gauge code `[04:a,b]` are the WORD ADDRESSES of the current and the maximum value, not the values (`HandleGaugeCode` loads them with `LDA $0000, Y` and passes them on; `DrawGaugeBar` reads through them). The notes and the enemy-gauge string wording follow the code.
  - In `NameEntryFrameText` the `[09]` (one-row font) comes after the name `[02:2]`: only the eight placeholders are one-row, the name line is two-row.
  - `LoadMenuBg2Graphics` moves `$2000` bytes (8 KB, 256 4bpp tiles), not 4 KB; the VRAM destination is word `$2000` (byte `$4000`), which is where the older '4 KB' reading came from.
  - The caller names in the FM-A6 text (`common_actor_00729D_part2.code_007638`, `lib_shared_014789`, `lib_0118FC_part3` and others) belong to the pre-regroup layout; the notes cite the current file and label names.
- **`$1B84` is `text_delay`.** The new-game value 3, the delay use in `TickAfterGlyph` and the zero tests in `HandleDelayCode`, `AdvanceDialogueLine` and `InitDialogueState` agree with OQ-I010-1; the ending-flag reading of FM-A2, FM-A4 and OQ-I024-2 is withdrawn in the notes (the `RunEnding` note and comment 21425 now say `text_delay`), the WRAM map and the question files cite it. OQ-I010-1 stays open for the byte-or-word question.
- **Two renderers compared.** `PrintTextString` (58 call sites in 10 files) is immediate, saves and restores `text_attr` and `text_font_flip` and forces DBR `$02`; `ShowDialogueText` (7 call sites: `Cop01_ShowText`, five sites in `lib_tile_triggers_and_lair_return`, the debug scanner) types with `text_delay`, waits for keys, scrolls and resumes, and never restores the text state. The block note of `lib_text_render` tabulates every control code against both.
- **Text readable from WRAM.** Both renderers read strings with DBR `$02`, so a string pointer below `$2000` reads WRAM through the low-RAM mirror (the player name `$1B92`, the debug buffer). This explains the two WRAM entries of `TextListPointers`.
- **Walkthrough check.** The name entry matches `01-in-the-beginning.md` (you pick a name; there is no default). The gauge colour rule (fifty units per bar, one colour per ten more HP, white at the top) matches `level-up.md`. The only spelling mismatch found is the dictionary entry `Deathtole` (OQ-I010-2, DISCREPANCY, unchanged). The credits text is not quoted in the walkthrough, so its spelling stays OQ-I010-11.
- **Ad-hoc scripts:** none were written. The only hand edits are `us/mnemonics.json` and `docs/wram-memory-map.md`, for which no tool exists.
