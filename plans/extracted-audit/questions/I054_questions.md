The walkthrough says "save point" and "file selection menu", the ROM says `Record`, `record` and `No1` to `No4` (a naming difference, not a mismatch). The number of files is not stated in the walkthrough; the ROM has four.

Static answers recorded in the document (and in the notes of `engine_title_file_select` and `lib_save_system`, `edits/I054.json`):

- OQ-I024-5: the fifth row of the file select is the text `Erase record` (`SaveSlotMenuText`; its cursor cell `$05CA` is `TitleMenuCursorOffsets[4]`), so the second prompt is the slot to erase; the carry of `LoadGameFromSlot` means "no valid save", and the walkthrough ("Opt for an empty file to begin") makes it the new game. The runtime half stays open as OQ-I054-1.
- OQ-I011-12: `[06:1,0452]` prints one BCD digit, the low nibble of the low byte of `saved_scene` (`HandleBcdNumberCode`: n = 1 digit), which is `world_index + 1`, the world number 1-7.
- The name field `$0447-$044F` is nine bytes (five word loads, the last overlapping the fourth), eight letters and the terminator of a full name; the same fact explains the terminator at `$1B9A` of OQ-I010-13.
- The notes said the file select loads the saved scene "after Continue"; there is no Continue row (rows: `No1` to `No4`, `Erase record`). Corrected in `lib_save_system` and in `docs/wram-memory-map.md`.
