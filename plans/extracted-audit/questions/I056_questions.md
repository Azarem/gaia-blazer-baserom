No DISCREPANCY: the game terms of the document (the title screen music, the singer and the Harp String with "the alternate music", the restaurant dog's joke, the Start pause) agree with `01-in-the-beginning.md`, `03-greenwood.md` and `07-king-magridds-castle.md` as far as static reading can check. The walkthrough says nothing about the music dropping out during the joke or the pause, so those two behaviours have no walkthrough claim to compare with.

Static answers recorded in the document (and in the notes and comments of `edits/I056.json`). All of them read the SPC side from `docs/audio/spc-disassembly.md` and the CPU side from `extracted/`; none was run:

- OQ-I024-1 (what the two sound bytes mean): the low byte of `sound_request` goes to `APUIO2` (SPC `$F6`) and asks for a sound on SFX voice 7, the high byte (`$0399`) goes to `APUIO3` (`$F7`) and asks for voice 8; bit 7 of the low byte plays the sound on both voices; bits 0-5 are the sound id, which `SFXInitChannel` turns into the pointer at `ARAM $2400 + 2 × id`. All 289 `BRK` sites (57 distinct operands) have an id in 1-`$26`, the 38 sounds of the table (89 sites use the low byte, 200 the high byte, 46 set bit 7).
- OQ-I025-2 (the direction of the `$F1` fade): `HandleFadeIn` sets the fade flag `$30` = `$FF` and the counter `$31` = `$7F`; each tick `$31` counts down and scales the volume of every voice, at 0 the SPC sets its current command `$04` = 0 and runs `StopAllChannels`. It is a fade-out, and the 0 on `APUIO0` that `MusicLoadWaitSilence` waits for is the end of it. The `$01` answer of `MusicLoadWaitFadeAck` is needed because a command of `$F0` or more is dispatched again on every tick while the port holds it (`ProcessSequenceTick` jumps to `DispatchCommand` first), which would reload `$31` each time.
- OQ-I013-6 (`$F2` and `$01` at the pause): `$F2` runs `SetEchoBit6` (bit 6 of SPC byte `$48`) and, because the port keeps it, stops the sequence from advancing; the `$01` is below `$F0` and equals the song the SPC already plays (`$08`), so nothing restarts and the same routine clears bit 6 and resumes. Runtime half: OQ-I056-3.
- OQ-I035-3 (the dog's 0 and 1): 0 is a song number different from the playing 1, so `PlaySong` keys off the music voices (`UpdateEnableMask`) and sets `$04` = 0, which stops the sequence; the later 1 differs from the stored 0, so `PlaySong` starts song 1 again from its first phrase. The tune restarts, it is not resumed. Runtime half: OQ-I056-2.
- OQ-I042-6 (the formats): the driver block and all 21 songs are five IPL records closed by a record of length 0 whose destination word is the sample count (low byte) and the first sample index (high byte), then one index byte per further sample. Driver: `$2E00` (78 bytes, 13 instruments), `$2F00` (24), `$2400` (1616: a table of 39 words and the 38 sound sequences), `$2C00` (52: 13 directory entries), `$0FFF` (1: `$0D`). Song: `$2E4E` (6 per instrument), `$2F00` (24, the same bytes in all 22 streams), `$1000` (53-5044, the sequence data, first word `$1002`), `$2C34` (4 per sample), `$0FFD` (2: the end of the samples). The 22 streams tile to their last byte; every directory entry and end pointer follows from `$3000` (driver) or `$7353` (songs) plus the sizes of `sfx00`-`sfx20` (all sizes are multiples of 9). `UploadSpcStream` is two handshakes: phase 1 sends the records, phase 2 sends the samples named by index from the table at `$07:8000`.
- OQ-I043-1 (static half): the SPC keeps no previous value of `$F6`/`$F7`; `SFXHandler` starts a sound whenever the port is non-zero. The word is a pulse, and the zero on odd frames is what lets the same id be requested again. Runtime half: OQ-I056-1.
- OQ-I042-5: the sine-wave mover at the start of `engine_spc_ipl_upload` is not SPC code. It has the skeleton of `we_enemy_arc_jet_*` (`COP A5` four-way, a wait of `$78`, `BRK #$5D`, seven passes, `$30` growing by `$10`) but moves the actor itself instead of placing flames; it still has no reference.
